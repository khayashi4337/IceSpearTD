## 1. コンセプト

> **「氷で道を描き、熱を砕き、夜空に咲かせる。」**

- 迷路を作る快感（自分の設計で敵がぐるぐる回る）
- 組み合わせを見つける快感（単体は弱い札が、3枚揃うと化ける）
- 運が弾ける快感（おみくじの大当たり演出）
- 眺める快感（倒した熱の塊が花火になって夜空に散る）

この4つの「快感」を一本の因果でつなぐ：

```
迷路を上手く作る → 敵が密集する → 範囲攻撃で連鎖撃破 → 花火が上がる
                                     ↓
                               おみくじの保留が溜まる → 大当たり → 良い札
                                                               ↓
                                                  組み合わせが完成 → さらに連鎖
```

運・腕前・設計が互いに強化しあう循環が、このゲームの背骨。

## 3. 基本ルール

### 3.1 盤面
- 論理グリッドは正方形タイル（ステージごとに 20×14 〜 26×18）。描画はアイソメトリック（2:1）。
- タイル種別：
  - `floor` 通行可・建設可
  - `rock` 通行不可・建設不可（地形の障害物。破壊不可）
  - `tree` 通行不可・建設不可（ステージ2）
  - `ice_floor` 通行可・建設可・上にいる敵の移動速度 +30%（ステージ4「滑る床」）
  - `lava` 通行可・建設不可・上を通った敵の熱 +5/タイル（ステージ4）
  - `spawn` 敵の出現口（1〜3個）
  - `core` 守るべき「氷の聖域」（ライフ）
- 1タイルには「氷壁」か「タワー」のどちらか1つしか置けない。**タワーも通行不可**（タワー自体も迷路の壁になる）。

### 3.2 プレイヤーの資源
| 資源 | 用途 | 入手 |
|------|------|------|
| 霊氷（ゴールド相当） | 氷壁、タワー建設、強化 | 撃破、ウェーブクリア報酬、利子（ウェーブ開始時に所持の5%、上限+30） |
| 聖域ライフ | 0でステージ失敗 | 初期20。敵が聖域に到達すると敵ごとのダメージ分減る |
| 保留（おみくじ玉） | おみくじを引く権利 | 連鎖撃破など（§6.2） |

### 3.3 配置と操作
| 操作 | マウス | キー |
|------|--------|------|
| 氷壁を置く | 左クリック（壁モード） / ドラッグで連続設置 | `W` で壁モード |
| タワーを置く | タワーを選んで左クリック | `1`〜`4` でタワー選択 |
| 選択解除 | 右クリック | `Esc` |
| 既存のタワー/壁を選択 | 左クリック → 情報パネル（強化・売却・特化） | — |
| 売却 | パネルのボタン | `S` |
| 一時停止 / 速度 | HUD ボタン | `Space` 一時停止、`F` 1x→2x→3x |
| 次ウェーブ前倒し | HUD ボタン（前倒しボーナス：残り時間に応じて霊氷） | `N` |

- 建設の取り消し：設置後 10 秒以内、かつそのウェーブ中に攻撃していなければ 100% 返金。
- 売却：建設・強化に使った総額の 60%。
- 設置プレビュー：置こうとした瞬間に新しい経路を計算し、予定経路を光る線で表示する。「完全封鎖になる」場合は線が赤くなり「熱で溶かされます」と表示する（置くことはできる）。

### 3.4 経路探索と「溶かす」ルール（Q2/Q7 の核）
敵は **重み付き最短経路**（A* / ダイクストラ）で聖域を目指す。
- `floor` のコスト = 1
- `ice_floor` のコスト = 0.8
- `lava` のコスト = 1（ただし熱が溜まる）
- **氷壁のコスト = 壁の残り耐久 ÷ その敵の融解力 × 係数 k（初期値 k=1.0）**（「溶かして通り抜けるのに何タイル分の時間がかかるか」の換算）
- タワーのコスト = ∞（タワーは溶かさない。※ボス「溶岩ゴーレム」だけはタワーも攻撃できる）

これにより：
- 迷路が短ければ敵は迂回する（通常の迷路TD）。
- 迷路を長くしすぎると、**薄い壁を溶かして近道したほうが安い** と敵が判断して壁を溶かし始める（完全封鎖をしなくても起きる）。
- 完全封鎖すると全敵が「一番安く溶かせる壁」に集まる → **わざと封鎖して、溶かしている壁の前に範囲攻撃を集中させる** という戦術が成立する。

**タワーだけで（壁を使わずに）道を完全に塞ぐ配置は禁止**（タワーは溶かせないため、敵が進めなくなる）。設置プレビューで×印を出し、置けない。

経路の再計算は、壁やタワーが増減したときと、壁の耐久が 25% 刻みで減ったときに行う。敵は「同じ流入口 × 同じ融解力区分」ごとにまとめて計算する（フローフィールド）。

### 3.5 熱（Heat）— 迷路の長さへの対価
- すべての敵は熱 `heat`（0〜100）を持つ。
- 移動1タイルごとに heat +1（敵種で係数あり）。`lava` 上は +5。
- 冷気系の命中で heat が減る（タワーごとの `chill` 値）。
- 段階効果：

| heat | 効果 |
|------|------|
| 0〜29 | なし |
| 30〜59 | 「火照り」移動速度 +15% |
| 60〜89 | 「灼熱」融解力 ×2、被ダメージ −10% |
| 90〜100 | 「発火」隣接する氷壁に毎秒ダメージ（触れているだけで溶かす）。見た目が赤く燃え上がる |

- 迷路を長くするほど敵は heat を溜めて強くなる。冷気で heat を削るタワーの価値が上がる。
- heat が高い敵は **燃焼・凍結との反応が大きい**（§5.3。蒸気爆発の威力は heat に比例）。heat を溜めさせて一気に爆破する、というハイリスクな戦術もある。

### 3.6 ウェーブ
- 各ステージは 10 ウェーブ。ウェーブ間の準備時間は 20 秒（前倒し可）。
- 10 ウェーブ目はボス。5 ウェーブ目は中ボス。
- ウェーブ内は複数の「群（group）」で構成し、群ごとに敵種・数・間隔・流入口・開始遅延を指定する。
- ウェーブの開始前に「次ウェーブ予告」（敵種アイコンと数）を表示する。

### 3.7 勝敗
- 10 ウェーブ目の全滅で勝利 → 花火大会（§7）→ リザルト → 紙芝居。
- 聖域ライフ 0 で敗北 → そのウェーブの開始時点からやり直す「巻き戻し」が1ステージ2回まで使える（文哉が投げ出さないための救済）。
- 星評価（1〜3）：クリア / ライフ15以上 / 「花火の格」が「スターマイン」以上。

### 4.3 強化と合成（文哉の「特化」案）
文哉のアイデア（`docs/legacy-ideas/TowerLebelupIdea.pu`）を正式仕様にする。

- **レベル**：Lv1〜Lv5。
- Lv1→Lv2、Lv2→Lv3 は霊氷で強化（費用：建設費 ×1.0、×1.5）。
- Lv3→Lv4、Lv4→Lv5 は **合成** でのみ到達する：同じレベルのタワー2基を選んで合成する。
  - 合成先は親1の種類になる。親2は消える（親2の場所は空き地になり、迷路が変わる → これも判断のうち）。
  - 子は親1と親2の **特化** を引き継ぐ（スロットの上限を超える分はプレイヤーが選んで捨てる）。
  - 異なる種類同士の合成は「混成」になる：親1の種類のまま、親2の主タグをサブタグとして獲得する。
- **特化スロット**：Lv1:1、Lv2:1、Lv3:2、Lv4:3、Lv5:4。
- **ゲームバランス階級（gameBalanceTier）**：文哉の案の `gameBalanceTier` はタワー強さの内部指標として使う（シミュレーションの出力とUI上の★表示に対応）。

`TowerAttributes`（文哉案のフィールドをそのまま採用）：

```ts
interface TowerAttributes {
  towerSynthesisLevel: 1 | 2 | 3 | 4 | 5; // Tower合成Level
  towerName: string;
  gameBalanceTier: number;   // シミュレーションで算出した強さ指標
  parentTower1?: TowerId;    // 合成元1
  parentTower2?: TowerId;    // 合成元2
  tokka: TokkaId[];          // 特化（スロット数はレベルで決まる）
}
```

## 5. デッキ構築（組み合わせで強くなる）

設計原則：
1. **単体は控えめ、組み合わせると掛け算**。どの札も単体での効果は「あれば少し嬉しい」程度にする。
2. **枠に上限**がある（特化スロット、護符枠、デッキ枚数）。全部は取れない。
3. **強い札には副作用**。
4. **組み合わせの発見を楽しくする**。図鑑に「発見済みの反応」を記録し、初発見は大きく演出する。

## 6. おみくじ（パチンコ演出）

### 6.1 原則
- **課金・ゲーム外のお金とは一切つながらない**（固定・変更不可）。
- 運が決めるのは「選択肢の質（レア度・枚数）」。最後に選ぶのは常にプレイヤー。
- 結果は抽選の瞬間に確定し、演出は結果に応じて選ぶ（パチンコと同じく「演出が結果を決める」のではない）。乱数はシード付き（再現・テストできる）。

### 6.2 保留（引く権利）の溜め方
保留は最大4個（HUDに玉として並ぶ）。

| 条件 | 保留 |
|------|------|
| 1回の攻撃・反応で3体以上を同時撃破 | +1 |
| 反応（R1〜R8）を初めて起こした（そのステージ内で種類ごとに1回） | +1 |
| ウェーブをライフ無傷でクリア | +1 |
| ボス・中ボス撃破 | +2 |
| ウェーブクリア時に保留0だった | +1（必ず1回は引ける） |

保留はウェーブ間（準備時間中）にまとめて引く。戦闘中に引くことはできない（戦闘の邪魔をしない）。

### 6.3 抽選テーブル（初期値）
| 結果 | 確率 | 出る札 | 選べる数 |
|------|------|--------|----------|
| 大吉 | 4% | レア以上確定 + 護符1枚が候補に入る | 4択から2枚 |
| 吉 | 12% | レア1枚以上 | 3択から1枚 + 霊氷 +50 |
| 中吉 | 24% | アンコモン1枚以上 | 3択から1枚 |
| 小吉 | 30% | コモン中心 | 3択から1枚 |
| 末吉 | 20% | コモン | 2択から1枚 + 次回の大吉率 +2% |
| 凶 | 10% | 凶札（§5.5）2択か「見送り（霊氷 +30）」 | 次のウェーブの敵 HP +10%、**次回の大吉率 ×2** |

- **天井**：吉以上が出ないまま 8 回引いたら、9 回目は大吉確定（「天井演出」専用のカットインあり）。
- 凶にも意味を持たせる：強い凶札が手に入る／次の大吉が近づく。凶を引いても「ちょっと嬉しい」ようにする。

### 6.4 演出の段階（予告とリーチ）
抽選結果が確定した後、結果に応じた確率で以下の演出を選ぶ。

1. **保留変化予告**：HUD の保留玉の色が変わる。白 → 青 → 緑 → 赤 → 金 → 虹。
2. **ステップアップ予告**：雪の結晶が画面を舞い、段階（STEP1〜5）が上がる。
3. **群予告**：雪うさぎの群れが画面を横切る。
4. **リーチ**：おみくじ筒が揺れ、「吉」と「大吉」の札が交互に見える。
5. **擬似連**：一度止まりかけて「再始動」（1〜3回）。回数が多いほど期待度が高い。
6. **カットイン**：ユキネ（通常）/ フミヤ（激アツ・金枠）/ セツナ（虹・大吉確定）。
7. **当否**：
   - 大吉：画面全体が凍りつく → ひびが入る → 砕け散って虹色の光と大量の花火。専用ファンファーレ。
   - 吉：金の札が開き、紙吹雪。
   - 中吉〜末吉：札が開く（短め）。
   - 凶：画面が一瞬赤く熱を帯び、ユキネが「…でも、次は来ますよ！」と励ます。

#### 予告ごとの期待度（その演出が出たときの「吉以上」の確率の目安）
| 演出 | 吉以上の期待度 |
|------|---------------|
| 保留：青 | 25% |
| 保留：緑 | 40% |
| 保留：赤 | 65% |
| 保留：金 | 85% |
| 保留：虹 | 100%（大吉確定） |
| ステップアップ STEP4 到達 | 60% |
| 群予告 | 70% |
| 擬似連 3回 | 80% |
| フミヤ・カットイン | 90% |
| セツナ・カットイン | 100%（大吉確定） |

演出の選択は「結果ごとの出現率テーブル」で実装し、上の期待度になるように逆算する（`src/core/omikuji/` のテストで検証する）。

### 6.5 演出の長さ（Q17）
設定で選べる：
- **フル**（初期値）：すべて見る。大吉は最大 12 秒。
- **激アツのみフル**：期待度 65% 未満の演出は 2 秒以内に省略。
- **倍速**：すべて 2 倍速。
- クリックでいつでもスキップできる（大吉の当否の瞬間だけは 0.5 秒待つ）。

## 7. 花火

### 7.1 戦闘中の花火化
敵は「熱の塊」なので、倒すと熱が夜空に弾ける。
- 通常撃破：小さな火花（数粒）。
- 同時撃破 3体以上 / 反応での撃破：撃破地点から **打ち上げ花火**（小玉）。
- 誘爆の連鎖：連鎖が1つ進むたびに色を変えて大きくする（連鎖8で「八重芯」）。
- ボス撃破：尺玉 + 画面の明るさ演出。
- 同時に出せる花火の数には上限を設ける（パーティクルのプールで管理。上限を超えたら古いものから消す）。

### 7.2 ウェーブクリア後の花火大会
ウェーブクリアごとに 3〜6 秒の花火大会。その回の成績で **花火の格** が決まる。

| 格 | 条件（スコア） | 内容 |
|----|----------------|------|
| 線香花火 | 〜999 | 小玉が数発 |
| 打ち上げ | 1000〜2999 | 小玉・中玉 |
| スターマイン | 3000〜5999 | 連続打ち上げ |
| ナイアガラ | 6000〜8999 | 画面上部から光の滝 + スターマイン |
| 尺玉 | 9000〜 | 大玉 + 全部乗せ |

スコア = 撃破数×10 + 反応回数×50 + 最大連鎖×200 + （ライフ無傷 ? 1000 : 0） + 前倒し秒数×20。

### 7.3 鑑賞モード
- ステージクリア時、UI を消して花火だけを眺めるモード（BGM はしっとり系に切り替え）。
- 好きなだけ眺められる。クリックで次へ。
- タイトル画面からも「花火鑑賞」でいつでも見られる（そのステージで記録した最高の格の花火大会を再生）。

## 10. ゲームバランスの方針と検証

### 10.1 方針
- 単体の札でクリア率が大きく変わってはいけない（§10.3 の基準）。
- 2〜3枚の組み合わせでクリア率・スコアが大きく伸びるのが正しい。
- 隠し壊れコンボ（§5.4）は例外として意図的に強い。

### 10.2 シミュレーション
- ゲームのルール部分（`src/core/`）は描画から完全に切り離し、Node 上で画面なしに回せるようにする。
- 乱数はすべてシード付きの1つの乱数源から取る（`Math.random()` は使わない）。
- 自動プレイヤー（ボット）を複数用意する：
  - `greedy`：経路が最も長くなる位置に壁、射程内の経路タイル数が最大の位置にタワー。
  - `blocker`：わざと完全封鎖して、溶かされる壁の前にタワーを集める。
  - `random`：ランダム配置（基準線）。
- `npm run sim -- --stage 1 --bot greedy --seeds 200 --cards all-pairs` で、札の組み合わせ総当たりのクリア率・スコアを CSV に出す。

### 10.3 合格基準（CI で確認する）
- 札1枚を足したときのクリア率の上昇が +15 ポイントを超える札は無い。
- 隠しコンボ以外で、上位1%の組み合わせのスコアが中央値の 3倍を超えない。
- 各ステージ、`greedy` ボットの札なしクリア率が：ステージ1 90%以上、2 70%、3 55%、4 45%、5 35%（人間はボットより上手い前提）。
- `blocker` 戦術が `greedy` より常に強い／常に弱い、のどちらにもならない（ステージごとに勝ち負けが入れ替わる）。

## 11. 技術設計

### 11.1 スタック
- TypeScript（strict）、Phaser 3.90.0、Vite、Vitest、ESLint、Prettier。
- 実行：PC のブラウザ。公開は GitHub Pages（`npm run build` → `dist/`）。

### 11.2 層の分け方
```
src/
  core/        # ゲームのルール。Phaser も DOM も import しない（テストで強制）
    math/      # 乱数(シード付き)・ベクトル・グリッド
    grid/      # 盤面、タイル、配置判定
    path/      # 重み付き経路探索・フローフィールド
    sim/       # World（固定ステップ step(dt)）、エンティティ、ウェーブ進行
    combat/    # 攻撃、弾、ダメージ、状態異常、heat
    synergy/   # タグ数え、段階ボーナス、反応判定
    omikuji/   # 抽選、天井、演出の選択
    economy/   # 霊氷、利子、売却
    events.ts  # core → 描画への出来事（Damage, Kill, Reaction, WallCrack, ...）
  data/        # 数値と定義（タワー・敵・札・反応・ウェーブ・ステージ・おみくじ表）。型付きの TS/JSON
  game/        # Phaser 層
    scenes/    # Boot, Title, Story, Map, Loadout, Battle, Omikuji, Fireworks, Result, Codex, Settings
    render/    # アイソメ変換、深度ソート、スプライト管理
    fx/        # パーティクル、花火、ヒットストップ、画面揺れ、ダメージ数字
    audio/     # ZzFX のラッパー、効果音定義、BGM
    ui/        # HUD、パネル、ボタン
    input/     # マウス・キー
  save/        # localStorage（try/catch）
tools/
  sim/         # 画面なしのバランスシミュレーション
art/
  blender/     # bpy スクリプト（モデル・リグ・レンダリング）
  concept/     # 画像生成AIの素案（Codex CLI で生成）
  prompts/     # 画像生成のプロンプト
public/assets/ # 書き出し済みのスプライトシート・音
```

- core は固定ステップ（1/60 秒）。描画層は core の状態を読み、`events` を受け取って演出を出す。core は演出のことを知らない。
- ヒットストップや倍速は「core を何ステップ進めるか」で実現する。

### 11.3 素材の契約
- スプライトシート：`public/assets/sprites/<id>.png` と `<id>.json`（Phaser の atlas JSON 形式）。
- アニメーション名：`<anim>_<dir>`（例：`walk_se`、`attack_n`）。方向がないものは `<anim>`。
- 一覧：`public/assets/manifest.json` に `{ id, kind, frameSize, anchor, anims: { name: { frames, fps, loop } } }`。
- 描画層は manifest を読み、素材が無い ID はプレースホルダー（コードで描いた図形）を **同じキー・同じアニメ名** で生成する。→ 素材が届けば、コードを変えずに差し替わる。
- アイソメのタイル：幅 128px × 高さ 64px（2:1）。ユニットの基準点は足元。
